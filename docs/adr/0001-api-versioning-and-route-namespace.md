# 0001. API 版本和路由命名空间

- 状态：Accepted
- 日期：2026-11-11

## 背景

短链创建 API 以后可能有不兼容改动，需要版本化。短链本身是发给用户的永久地址，不能因为 API 升级失效。之前短码和 `/healthz` 等路由共用顶层路径，需要维护保留字表。

## 决策

- 管理 API 使用 `/api/v1` 前缀，例如 `POST /api/v1/links`。
- 公开跳转固定在 `/r/{code}`，不加版本。
- `/healthz` 保持无版本。
- 短码只在 `/r/` 命名空间下，路由在其他命名空间，天然隔离。

## 后果

- 旧短链不会因为 API 版本升级失效。
- 新增路由不会和短码冲突，不需要保留字表。
- 短链比 `/{code}` 多两个字符。
- 如果未来要改跳转协议，需要保留 `/r/` 的旧行为，另开新路径。
