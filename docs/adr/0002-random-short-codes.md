# 0002. 随机短码

- 状态：Accepted
- 日期：2026-11-11

## 背景

最初方案是用自增 ID 做 Base62。自增 ID 可枚举，会暴露业务量；Snowflake 适合分布式唯一 ID，但短码会变长，而且仍然可以被猜出大致时间范围。短链的公开标识更需要不可预测。

## 决策

- `id` 继续由数据库自增，只作内部主键。
- 对外短码使用 8 位 Base62 随机字符串，`crypto/rand` + 拒绝采样生成。
- `code` 加唯一索引；插入遇到 23505 时重新生成，最多重试 5 次。
- 内存版和 PostgreSQL 版行为一致。

## 后果

- 短码不可按顺序枚举。
- 8 位空间约 2.18e14；1 亿条数据时单次碰撞概率约 4.6e-7，连续 5 次都碰撞约 2e-32。
- 创建通常只执行一次插入，碰撞重试对延迟影响可以忽略。
- 短码长度以后可以增加；已有短码仍然可以查询，因为匹配的是字符串。
- 不引入 Snowflake 的 node ID、时钟回拨等运维复杂度。
